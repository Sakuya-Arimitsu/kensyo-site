# 会社ホームページ（お知らせ・求人の更新の仕組み）

Webの知識がなくても、**GitHubのIssueに書き込むだけで**お知らせや求人を更新できるホームページです。更新作業はすべてGitHubの中で完結します。

```
① Issueフォームに分かる範囲で記入して作成
      ↓ 自動
② Claudeがコメントで質問・文章を提案
      ↓ 「@claude これでOK」とコメント
③ Claudeが下書きを保存 → 公開申請が自動で作られる
      ↓ 自動
④ 確認用ページに反映（https://hisazumi-test.com/kensyo-preview/）
      ↓ 見た目を確認して「Merge pull request」を押す
⑤ 本番サイトに反映（https://hisazumi-test.com/kensyo/）、Issueも自動で閉じる
```

- **予約公開**：公開日を未来にすると、その日の朝6時ごろに自動で公開されます
- **掲載終了**：掲載終了日を決めると、その日を過ぎたら自動で非表示になります
- **差し戻し**：すべての変更が履歴として残るので、いつでも前の状態に戻せます

## 担当者向け：使い方

### 準備（最初の1回だけ）

GitHubのアカウントを作り、管理者からリポジトリへの招待（書き込み権限）を受けてください。

### お知らせ・求人を出す

1. リポジトリの **「Issues」タブ → 「New issue」** を押します
2. やりたいことに合うフォームを選びます

   | フォーム | 使うとき |
   | --- | --- |
   | お知らせを作る | 新しいお知らせを出す |
   | 求人を出す | 新しい求人を出す |
   | 掲載中の内容を直す・取り下げる | 文章の修正、記事の取り下げ、募集の締め切り |
   | 前の状態に戻す（差し戻し） | 公開した内容を以前の状態に戻す |

3. タイトルの【　】のあとに短い説明を足し、**分かる範囲で**記入して「Create」を押します。写真は入力欄にドラッグ＆ドロップすれば添付できます
4. 1〜3分ほどで、Claudeがコメントで返事をします（質問、または文章の提案）
5. 返事にはコメントで答えます。**コメントの先頭に `@claude` を付けてください**（付けないとClaudeは反応しません）

   ```
   @claude タイトルは案2でお願いします。最後に電話番号も入れてください
   ```

6. 内容がよければ `@claude これでOK` とコメントします。Claudeが下書きを保存し、数分後にIssueに **「公開申請を作りました」** というコメントが届きます

### 確認して公開する

1. 届いたコメントのリンクから **公開申請** のページを開きます
2. ページ内の **確認用ページ** のリンクを開き、見た目を確認します（上部に黄色い「確認用ページです」の帯が出ます）
3. 直したいところがあれば、公開申請のページの一番下のコメント欄に `@claude ○○を直してください` と書きます。数分後に確認用ページが更新されます
4. 問題がなければ、公開申請のページで **「Merge pull request」→「Confirm merge」** を押します。2〜3分後に本番サイトに反映され、元のIssueも自動で閉じます

### 注意

- **1つのIssueでは、1つの記事・求人だけ**を扱います。別の記事は新しいIssueで依頼してください
- 公開申請ができたあとの修正は、**公開申請のページ**でコメントしてください（元のIssueでは頼まないでください）
- 確認用ページはみんなで1つを共有しています。ほかの人の下書きが表示されていることもあります
- Claudeのコメントに出る「Create PR」のリンクは使いません（公開申請は自動で作られます）

### 困ったとき

| 困りごと | 対処 |
| --- | --- |
| Claudeが返事をしない | コメントに `@claude` が付いているか確認してください。Issueを作った直後に返事がない場合も、`@claude お願いします` とコメントすれば動きます |
| 確認用ページが変わらない | 反映まで1〜2分かかります。ページを再読み込みしてください |
| 急いで本番から消したい | 「Pull requests」タブの「Closed」から、その内容を公開したときの公開申請を開き、一番下の「Revert」→ 新しくできた公開申請で「Merge pull request」→「Confirm merge」を押すと、2〜3分で元に戻ります |
| デザインを変えたい | 管理者に相談してください |

## 管理者向け：初期設定

### 1. ファイルをリポジトリに置く

このフォルダの中身を、リポジトリ（kensyo）の直下に置きます。

- 以前の検証で使った `index.html` は削除します（ページは `build.py` が自動で作るため）
- `.github/workflows/` の `deploy.yml` と `claude.yml` は、この新しいものに置き換えます

### 2. GitHubの設定

1. **ラベルを作る**：Actionsタブ →「初期設定（ラベルを作る）」→「Run workflow」を1回実行します。Issueフォームが使うラベル（claude、お知らせ、求人、修正、差し戻し）が作られます
2. **公開申請の自動作成を許可する**：Settings → Actions → General の一番下「Workflow permissions」で、**「Allow GitHub Actions to create and approve pull requests」にチェック**を入れて保存します
3. **シークレットを確認する**：`CLAUDE_CODE_OAUTH_TOKEN`、`FTP_SERVER`、`FTP_USERNAME`、`FTP_PASSWORD` が登録済みであること（今までのものをそのまま使います）
4. **担当者を招待する**：Settings → Collaborators から、担当者のGitHubアカウントを招待します（Write権限）。Claudeは書き込み権限のある人のIssue・コメントにだけ反応します

### 3. アップロード先

| 用途 | ワークフロー | アップロード先 |
| --- | --- | --- |
| 確認用 | `preview.yml` | `public_html/kensyo-preview/` |
| 本番 | `deploy.yml` | `public_html/kensyo/` |

本番のドメインが決まったら、`deploy.yml` の `server-dir`、`CLAUDE.md` と `auto-pr.yml` に書かれているURLを書き換えてください。

### 4. 確認用ページにパスワードをかける（推奨）

確認用ページは検索エンジンに載らない設定にしていますが、URLを知っていれば誰でも見られます。Xserverのサーバーパネルの「アクセス制限」で、`kensyo-preview` フォルダにユーザー名とパスワードを設定しておくと安心です。

### 5. 会社情報を入れる

`site.yml` の会社名、紹介文、所在地、連絡先などを実際の内容に書き換えます。サンプルのお知らせ・求人（`content/` の中身）は、不要になったら削除してください。

### 6. 動作確認

1. main に反映すると「本番サイトに公開」が動き、`https://hisazumi-test.com/kensyo/` にサイトが表示されます
2. 「お知らせを作る」フォームでテスト用のIssueを作り、Claudeの返事 → `@claude これでOK` → 公開申請 → 確認用ページ、の流れを確認します。テストが終わったら、公開申請は「Close pull request」で閉じてください

## 仕組みの詳細

### ワークフロー

| ファイル | 動くとき | すること |
| --- | --- | --- |
| `claude.yml` | 「claude」ラベル付きのIssueが作られたとき、`@claude` のコメントがあったとき | Issueの画像をダウンロードし、Claudeが返事・作業をする |
| `auto-pr.yml` | Claudeが下書き（`claude/` で始まるブランチ）を保存したとき | 公開申請を作り、元のIssueにリンクを知らせる |
| `preview.yml` | main 以外のブランチに保存されたとき | 確認用ページを生成してアップロード |
| `deploy.yml` | main に反映されたとき、毎朝6時ごろ | 本番ページを生成してアップロード、公開の記録（タグ）を残す |
| `setup-labels.yml` | 手動（最初に1回） | ラベルを作る |

### ファイル構成

```
├── content/
│   ├── news/          お知らせ（1記事＝1ファイル）
│   └── jobs/          求人（1職種＝1ファイル）
├── images/            記事や求人で使う画像
├── templates/         ページのひな形（デザイン）
├── assets/css/        デザインの色や文字の設定
├── site.yml           会社情報
├── build.py           ページを生成するプログラム
├── CLAUDE.md          Claudeへの作業ルール
├── .claude/skills/    Claudeの作業手順（お知らせ・求人・差し戻し）
└── .github/
    ├── ISSUE_TEMPLATE/  Issueの入力フォーム
    ├── scripts/         画像ダウンロード・公開申請の文面づくり
    └── workflows/       自動処理の設定
```

### 記事の状態

| status | 本番サイト | 確認用ページ |
| --- | --- | --- |
| 公開（公開日が今日以前） | 表示 | 表示 |
| 公開（公開日が未来） | 公開日の朝6時ごろから表示 | 「公開予定」の印付きで表示 |
| 下書き | 表示しない | 「下書き」の印付きで表示 |
| 非公開 | 表示しない | 表示しない |

掲載終了日（`end_date`）を過ぎたものは、どちらにも表示しません。

### 手元でページを生成する

```
pip install -r requirements.txt
python build.py            # 本番用
python build.py --preview  # 確認用
python build.py --check    # データのチェックだけ
```

生成されたページは `dist/` フォルダに入ります。

### バックアップと差し戻し

- 変更はすべてGitの履歴に残ります。本番に公開するたびに `release-日付-時刻` のタグも付きます
- 担当者は「前の状態に戻す（差し戻し）」フォームでIssueを作れば、Claudeが履歴を調べて戻します（手順は `.claude/skills/restore/SKILL.md`）
- 記事は削除せず「非公開」にする運用なので、取り下げた記事もすぐ復活できます

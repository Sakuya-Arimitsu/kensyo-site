# 会社ホームページ（お知らせ・求人の更新の仕組み）

Webの知識がなくても、**Claudeとチャットするだけで**お知らせや求人を更新できるホームページです。

```
担当者がClaudeに相談（チャット）
  ↓ Claudeが文章を提案 → 担当者がOK
Claudeが下書きとして保存
  ↓ 自動
確認用ページに反映（https://hisazumi-test.com/kensyo-preview/）
  ↓ 担当者が見た目を確認して「公開ボタン」を押す
本番サイトに反映（https://hisazumi-test.com/kensyo/）
  ↓ 自動
公開の記録（バックアップの目印）が残る
```

- **予約公開**：公開日を未来にすると、その日の朝6時ごろに自動で公開されます
- **掲載終了**：掲載終了日を決めると、その日を過ぎたら自動で非表示になります
- **差し戻し**：すべての変更が履歴として残るので、いつでも前の状態に戻せます

## 担当者向け：使い方

### 準備（最初の1回だけ）

1. Claudeのアカウント（Pro以上のプラン）と、GitHubのアカウントを用意します
2. 管理者に、GitHubのリポジトリへの招待（書き込み権限）をもらいます
3. ブラウザで https://claude.ai/code を開き、画面の案内に沿ってGitHubと連携します。スマートフォンなら、Claudeアプリの「Code」タブから使えます

### 更新するとき

1. https://claude.ai/code を開き、このリポジトリを選んで新しい会話を始めます
2. やりたいことを、普段の言葉で書きます（下の例を参考に）
3. Claudeの質問に答え、提案された文章を確認します。直したいところは「もっと短く」「やわらかい言い方に」のように伝えます
4. 「これでOK」と伝えると、Claudeが下書きとして保存し、確認用ページのURLを教えてくれます
5. 確認用ページで見た目を確認します（上部に黄色い「確認用ページです」の帯が出ます）
6. 問題なければ「公開して」と伝えます。Claudeの案内に沿って、GitHubの画面で **「Merge pull request」→「Confirm merge」** を押すと、2〜3分で本番に反映されます

**1つの会話では、1つの記事・求人だけ**を扱ってください。別の記事は新しい会話で始めます。

### 指示の例

| やりたいこと | 書き方の例 |
| --- | --- |
| お知らせを出す | 年末年始休業のお知らせを出したいです。12/29〜1/4がお休み。12月1日に公開したい |
| チラシからお知らせを作る | （画像を添付して）このチラシの内容で、イベントのお知らせを作ってください |
| 求人を出す | パートの配送スタッフを募集したいです。午前中だけ、週3日〜、時給1,100円 |
| 求人の条件を変える | 一般事務の求人の給与を「月給23万円〜」に変えたい |
| 募集を締め切る | 配送スタッフの募集を今月末で締め切りたい |
| 記事を取り下げる | 「ホームページを公開しました」のお知らせを消したい |
| 前の状態に戻す | 昨日公開したお知らせを、公開前の状態に戻したい |
| 確認だけしたい | 今公開しているお知らせと求人の一覧を見せて |

### 困ったとき

- **確認用ページが変わらない**：反映まで1〜2分かかります。ページを再読み込みしてください。確認用ページはみんなで1つを共有しているため、ほかの人の下書きが表示されていることもあります
- **急いで本番から消したい**：GitHubで、その変更の公開申請（プルリクエスト）を開き、一番下の「Revert」→ 新しくできた公開申請で「Merge pull request」→「Confirm merge」を押すと、2〜3分で元に戻ります
- **デザインや会社情報を変えたい**：管理者に相談してください

## 管理者向け：初期設定

### 1. ファイルをリポジトリに置く

このフォルダの中身を、リポジトリ（kensyo）の直下に置きます。

- 以前の検証で使った `index.html` は削除します（ページは `build.py` が自動で作るため）
- `.github/workflows/deploy.yml` は、この新しいものに置き換えます
- `.github/workflows/claude.yml`（Issueから呼び出す仕組み）は、そのまま残しても問題ありません

### 2. GitHubの設定を確認する

- **シークレット**：`FTP_SERVER`、`FTP_USERNAME`、`FTP_PASSWORD` が登録済みであること（今までのものをそのまま使います）
- **担当者の招待**：Settings → Collaborators から、担当者のGitHubアカウントを招待します（Write権限）
- **Claude GitHub App**：リポジトリにインストール済みであること

### 3. アップロード先を確認する

| 用途 | ワークフロー | アップロード先 |
| --- | --- | --- |
| 確認用 | `preview.yml` | `public_html/kensyo-preview/` |
| 本番 | `deploy.yml` | `public_html/kensyo/` |

本番のドメインが決まったら、`deploy.yml` の `server-dir` と、`CLAUDE.md` に書かれているURLを書き換えてください。

### 4. 確認用ページにパスワードをかける（推奨）

確認用ページは検索エンジンに載らない設定にしていますが、URLを知っていれば誰でも見られます。Xserverのサーバーパネルの「アクセス制限」で、`kensyo-preview` フォルダにユーザー名とパスワードを設定しておくと安心です。

### 5. 会社情報を入れる

`site.yml` の会社名、紹介文、所在地、連絡先などを実際の内容に書き換えます。サンプルのお知らせ・求人（`content/` の中身）は、不要になったら削除してください。

### 6. 動作確認

1. main に反映すると「本番サイトに公開」ワークフローが動き、`https://hisazumi-test.com/kensyo/` にサイトが表示されます
2. claude.ai/code でリポジトリを選び、「テスト用のお知らせを下書きで作って」と頼み、確認用ページに表示されることを確認します

## 仕組みの詳細

### ファイル構成

```
├── content/
│   ├── news/          お知らせ（1記事＝1ファイル）
│   └── jobs/          求人（1職種＝1ファイル）
├── images/            記事や求人で使う画像
├── templates/         ページのひな形（デザイン）
├── assets/css/        デザインの色や文字の設定
├── site.yml           会社情報
├── build.py           ページを生成するプログラム
├── CLAUDE.md          Claudeへの作業ルール
├── .claude/skills/    Claudeの作業手順（お知らせ・求人・差し戻し）
└── .github/workflows/ 自動アップロードの設定
```

### 記事の状態

| status | 本番サイト | 確認用ページ |
| --- | --- | --- |
| 公開（公開日が今日以前） | 表示 | 表示 |
| 公開（公開日が未来） | 公開日の朝6時ごろから表示 | 「公開予定」の印付きで表示 |
| 下書き | 表示しない | 「下書き」の印付きで表示 |
| 非公開 | 表示しない | 表示しない |

掲載終了日（`end_date`）を過ぎたものは、どちらにも表示しません。

### 手元でページを生成する

```
pip install -r requirements.txt
python build.py            # 本番用
python build.py --preview  # 確認用
python build.py --check    # データのチェックだけ
```

生成されたページは `dist/` フォルダに入ります。

### バックアップと差し戻し

- 変更はすべてGitの履歴に残ります。本番に公開するたびに `release-日付-時刻` のタグも付きます
- 担当者は、Claudeに「前の状態に戻したい」と頼めば差し戻せます（手順は `.claude/skills/restore/SKILL.md`）
- 記事は削除せず「非公開」にする運用なので、取り下げた記事もすぐ復活できます

# 前の状態に戻す（差し戻し）

このサイトでは、保存したすべての変更が履歴として残っている。これがバックアップになっている。本番に公開するたびに `release-日付-時刻` という目印（タグ）も付いている。

## 1. 何を戻すか聞く

- **記事ひとつ**を戻すのか、**サイト全体**をある日の状態に戻すのか
- いつの状態に戻したいか（「昨日の公開前」「10月1日の時点」など、あいまいでよい）

## 2. 履歴を調べる

```
git fetch --unshallow --tags 2>/dev/null || git fetch --tags
TZ=Asia/Tokyo git log --date=format-local:'%Y-%m-%d %H:%M' --pretty='%h %ad %s' -- content site.yml images
git tag -l 'release-*' --sort=-creatordate | head -20
```

特定の記事の履歴は `-- content/news/ファイル名.md` のように指定して調べる。

## 3. 戻す先を確認する

調べた結果を、担当者に分かる形の表で見せて、どこに戻すかを選んでもらう。英数字の記号（コミットの番号など）は見せない。

| 日時 | 内容 |
| --- | --- |
| 10月7日 15:30 | 求人「一般事務スタッフ」の給与を変更 |
| 10月5日 10:12 | お知らせ「ホームページを公開しました」を追加 |

選んでもらったら、**何がどう変わるか**（「給与が 月給25万円 から 月給22万円 に戻ります」など）を説明し、OKをもらってから作業する。

## 4. 戻す

- **記事ひとつ**：`git checkout <戻す先> -- content/news/ファイル名.md`
- **サイト全体**：`git checkout <戻す先> -- content site.yml images`
  - 戻す先の時点より後に追加された記事は、ファイルを消さずに `status: 非公開` にする
- **非公開にした記事を復活**：`status` を「公開」に戻すだけでよい

戻したあとは `git diff --stat` などで変更を確認し、CLAUDE.md の「保存のしかた」に従って保存する。確認用ページで表示を確かめてもらい、「公開のしかた」に従って公開する。

## 急いで本番を戻したいとき

担当者が「今すぐ本番から消したい」と急いでいる場合は、次の方法も伝える。

- GitHubで、問題の変更を公開したときの公開申請（プルリクエスト）を開く
- 一番下の「Revert」ボタンを押すと、取り消し用の公開申請ができる
- その公開申請で「Merge pull request」→「Confirm merge」を押すと、2〜3分で本番が元に戻る
